# Functional MVP: export, runtime data, and verified geography

**Status:** Completed
**Started:** 2026-09-13
**Scope:** Complete the local Ashburton–Hakatere MVP through filtered export,
runtime analytical-data optimization, local MapLibre geography, and deeper
transparency/accessibility verification.

## Objective

Replace the schematic map with a locally supplied MapLibre catchment view,
provide deterministic context-filtered CSV export, reduce repeated runtime
data without weakening provenance, and verify the primary workflow with
browser, accessibility, responsive, and performance evidence.

## Guardrails

- Keep the approved `published_unflagged` quality policy, parameter scope,
  windows, and conservative trend rules unchanged.
- Keep raw responses and generated observation assets ignored; no public
  deployment or licensing/freshness release decision is part of this plan.
- Preserve source identifiers, original result/unit fields, censoring, quality,
  exclusion, and analytical-eligibility meaning in the processing and export
  contracts.
- Prefer simple static assets and typed decoding; do not add a backend,
  database, binary format, service worker, or complex cache without measured
  need.

## Work units

1. Profile the current asset, inspect the map boundary/source evidence, and
   acquire the authoritative Ashburton polygon into ignored local runtime
   preparation inputs.
2. Define and generate a versioned compact runtime asset with shared metadata,
   local geometry, summaries/coverage/trends, and parameter-partitioned detail
   observations or an equivalently measurable loading strategy.
3. Implement MapLibre rendering with real local geometry and station features,
   deterministic filters, keyboard-equivalent station selection, and the
   existing accessible station control.
4. Implement deterministic UTF-8 filtered CSV export with explicit source,
   quality, censoring, eligibility, and exclusion columns.
5. Refine methodology/provenance/freshness/accessibility messaging and add
   unit, contract, and browser tests for export, decoding, map interactions,
   loading/error states, and keyboard workflow.
6. Measure before/after payload, compression, parse/load, and interaction
   behavior; inspect screenshots at 1440×900, 1024×768, and 390×844; run all
   applicable gates, update governance, archive the plan, and commit.

## Acceptance evidence

- The browser requests a local versioned geometry/runtime asset and displays the
  authoritative Ashburton polygon plus all 19 in-bound station coordinates.
- Map, controls, chart/table, summaries, and export share the active parameter,
  window, and station semantics; no-data, censored, excluded, and indeterminate
  states remain explicit.
- CSV export is deterministic, UTF-8, correctly escaped, context-filtered, and
  tested for station/all-site, no-data, Unicode, censored, and excluded rows.
- Runtime data is materially smaller or better staged than the 10.47 MB
  monolith, with retained provenance and documented contract/version decoding.
- Browser tests cover real-data load, map/control selection, determinate and
  indeterminate trends, censored data, export, failed assets, axe checks,
  console/network errors, keyboard access, overflow, and three viewports.
- The plan records measurements, skipped checks, limitations, and the next
  frontier before it is archived.

## Outcome

Completed on 2026-09-13. The former schematic/empty-style map was replaced by
local MapLibre rendering of the audited ECan Ashburton River polygon and 19
in-bound station coordinates. The runtime contract is now version 2.0.0 with
lookup-backed shell metadata and parameter-partitioned observations. The
dashboard exports deterministic UTF-8 CSV for the active context, preserving
quality, censoring, provenance, eligibility, and exclusion meaning.

Validation completed:

- `python3 -m unittest discover -s tests -v`: 33 passed.
- Fixture validation and Python compilation passed.
- `cd web && npm ci && npm run typecheck && npm run test:unit && npm run build` passed.
- `cd web && npm run test:browser`: 12 passed, including real asset loading,
  MapLibre geometry/selection, coordinated filters, export, fallback/error,
  keyboard, axe, performance, and responsive checks.
- Full-page screenshots at 1440×900, 1024×768, and 390×844 were inspected.
- No application console errors, page errors, failed requests, horizontal
  overflow, or serious/critical axe violations were observed. The only
  filtered browser diagnostic is the known headless Chromium/WebGL compositor
  message generated by MapLibre in this environment.

Measured delivery: the prior formatted monolith was 10,473,514 bytes; the new
shell is about 1.26 MB raw/82 kB gzip, shell plus initial E. coli detail about
1.41 MB raw/103 kB gzip, and all partitions about 1.71 MB raw/207 kB gzip.
Brotli tooling was unavailable in the environment. Initial runtime-ready
timing was about 183 ms in the local browser measurement. Public observation
publication, dataset-specific source terms, freshness/attribution release
checks, complete coverage, and deployment remain gated.
